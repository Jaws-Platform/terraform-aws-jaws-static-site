# Rules for coding agents

This file restates the repository conventions for coding agents. The
human-facing version, with setup and release details, is
[CONTRIBUTING.md](CONTRIBUTING.md).

## Non-negotiable

- **Never push to `main`.** Every change reaches `main` through a pull request.
  Direct pushes are blocked by a branch ruleset; do not try to work around it.
- **Open pull requests with a typed template and fill in every section:**

  ```sh
  gh pr create --template <type>.md   # feat.md | fix.md | docs.md | chore.md | refactor.md | ci.md
  ```

  Leaving a section empty or deleting it is not acceptable. `fix.md` also
  needs Bug, Root cause and Reproduction.
- **Pull request titles are Conventional Commits** (`type(scope)?: subject`,
  100 characters at most). The title becomes the squash-merge commit message.
- **Commits are a single line**: `type(scope)?: subject`, at most 100
  characters. After that line, only a blank line and
  `Co-authored-by: Name <email>` trailers are allowed. No body text; details
  go in the pull request description. Allowed types: `feat`, `fix`, `docs`,
  `chore`, `refactor`, `ci`, `build`, `perf`, `style`, `test`, `revert`.
  Breaking changes use `!` (`feat!: ...`).
- **Merges are squash or rebase only.** History stays linear.
- **Releases are made by merging the Release Please pull request**, which is
  authored by `jwallace145-release-bot[bot]`. Do not create tags or releases
  by hand, and do not edit `CHANGELOG.md` or `version.txt`.
- **Run the checks before opening a pull request:**

  ```sh
  scripts/check.sh
  ```

## Working in this repo

- The repository root is a module (the one the Terraform Registry shows
  first), and every building block lives in `modules/<name>/` with `main.tf`,
  `variables.tf`, `outputs.tf`, `versions.tf`, `README.md`, `examples/basic/`
  and `tests/`. Whole-scenario examples live in `examples/<name>/` at the
  root, which is where the registry looks for them.
- CI finds modules by their `versions.tf` (`scripts/list-modules.sh`), so a
  new module needs no workflow or ruleset change.
- `README.md` in each module is generated by terraform-docs between the
  `BEGIN_TF_DOCS` and `END_TF_DOCS` markers. Regenerate after any input or
  output change, or CI fails on the diff:

  ```sh
  terraform-docs --config .terraform-docs.yml modules/<name>   # or `.` for the root
  ```

- Tests use `terraform test` with mocked providers. CI has **no cloud
  credentials**; never write a test that needs them, and never run
  `terraform apply`.
- Modules never configure a provider and never take a tag map: resources get
  `Component` (and `Name` where they have one) from the module, and every
  other tag from the caller's provider `default_tags`.
- Keep the modules free of any one organisation's names. Names come from
  inputs such as `name` or `name_root`, which have no organisation-specific
  default; examples use `acme` and `example.com`.
- Usage snippets pin this module with a line that ends in
  `# x-release-please-version`. Release Please rewrites those lines at each
  release; keep the marker when you add a snippet.
- Any breaking change to a module's inputs or outputs is `feat!` or `fix!`:
  a rename, a removal, a changed type or default, or a resource name that
  forces replacement.
